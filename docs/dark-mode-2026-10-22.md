# Mode terang dan gelap — 22 Oktober 2026

## Audit sebelum perubahan
- Semua 22 page.tsx memakai root layout/provider bersama. Tailwind sudah mendukung class dark, tetapi belum ada palet gelap atau penyimpanan pilihan. Halaman 404 bawaan juga perlu mengikuti pilihan aplikasi, bukan hanya tema sistem.
- Mayoritas UI memakai token CSS. Kalender, badge, banner draf, dan dialog ekspor masih memiliki permukaan/teks warna terang tetap; perlu diperbaiki di komponennya.
- Native select/textarea memaksa color-scheme light. Grafik dan overlay kamera perlu diperiksa terpisah; gambar kamera dan berkas PDF/Excel tidak boleh dibalik warnanya.
- Pilihan Terang/Gelap ditempatkan di Pengaturan untuk semua peran, tersimpan per browser, diterapkan sebelum paint, termasuk halaman autentikasi. Default tetap terang. Tidak ada perubahan API/database.
- Validasi direncanakan: pemeriksaan tipe/lint, tes persistensi dan kegagalan storage, audit semua route, browser sintetis desktop/mobile serta kedua bahasa, dan build terpisah.

## Implementasi
- Pengaturan → Tampilan → Terang/Gelap, dengan preview dan status pilihan yang dapat dibaca pembaca layar. Tersedia bagi semua peran.
- ThemeProvider pada root dan palet CSS bersama mencakup sidebar, header, tabel, formulir, pesan, dialog, halaman autentikasi, admin, dan Face ID. Token warna juga dipakai kalender, draf, badge, serta dialog ekspor.
- Pilihan disimpan di localStorage `workflow-theme` pada browser/origin yang sama, bukan di akun/server. Tetap tersedia setelah logout; browser/perangkat lain tidak otomatis mengikuti.
- Script pada head menerapkan pilihan sebelum React dimuat. Default terang, nilai tidak valid kembali ke terang. Event storage menyelaraskan pilihan dari tab lain. Kegagalan menyimpan tidak menghalangi perubahan tampilan dan ditampilkan sebagai pesan.
- Halaman 404 sendiri mengikuti tema aplikasi. Preview mini terang/gelap sengaja memiliki warna tetap; gambar kamera, warna kategori grafik, dan isi PDF/Excel tidak dibalik.
- Tidak menambah dependensi, migrasi, endpoint, atau perubahan alur bisnis.

## Validasi
- Pemeriksaan tipe, ESLint, build produksi di folder terpisah, dan `git diff --check`: lulus.
- Delapan file tes terarah lulus: theme, i18n, settings-navigation, project-form-draft, dua deadline-calendar, dua project-report.
- Tes theme memeriksa bootstrap sebelum React, storage tidak tersedia/nilai tidak valid, serta kontras minimal 4,5:1 untuk pasangan teks/permukaan utama pada kedua palet. Ini bukan audit WCAG menyeluruh.
- Matriks browser: **100 pemeriksaan tampilan lulus**: 22 route × 2 tema × 2 ukuran (1440/360 px), ditambah kalender, dialog ekspor, dan 404 pada kedua tema/ukuran. Desktop menggunakan Inggris, mobile Indonesia. Matriks membandingkan daftar route dengan seluruh page.tsx agar route baru tidak terlewat.
- Seluruh peran dapat mengubah tema. Persistensi saat navigasi, reload/logout, bootstrap saat JavaScript Next diblokir, simulasi event lintas tab, reset preferensi, kegagalan storage, dan pemulihannya lulus. Tidak ditemukan runtime error, request API tidak dikenal, panel putih tak disengaja dalam mode gelap, atau overflow horizontal dalam matriks.
- Screenshot dashboard, pengaturan desktop/mobile, kalender mobile, formulir proyek, serta 404 diperiksa visual. Menggunakan Chrome headless dengan profil sementara dan respons API sintetis; tidak mengubah data pengguna atau menyalakan kamera. Ini pengujian UI dengan data simulasi, bukan pengujian ulang alur bisnis produksi atau semua browser.
- Perintah pengulangan: jalankan preview frontend lokal, lalu `node frontend/tests/browser/theme-browser.cjs` (default port 3036, dapat diatur dengan WORKFLOW_TEST_ORIGIN).
- Screenshot dan hasil mesin berada di `.cache/dark-mode/browser`; build log di `.cache/dark-mode-build.log`. Folder ini bukan berkas untuk commit.
